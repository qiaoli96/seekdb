# 材料自评（按 agent-learning-evidence-v3-unbounded 模拟评审）

> 这不是官方分。官方评审在 MySQL case 全过之后才触发，使用固定的模型/提示词/参数且三轮取中位数。
> 本文件是我按公开规则逐条对照的自评，目的是在浪费提测额度之前找出结构性缺陷。

## 1 逐单元严格判定

| 单元 | 维度 | 原申报 | 严格评审可得 | 判据 |
| --- | --- | --- | ---: | --- |
| U1 | 独立验证与质疑 | 1.5 | **1** | 学生提出质疑并触发验证，但『解释结果、据此修正、复测』由 Agent 完成；0.5 档要求无实际结果，我们确有结果，故 1 档 |
| U2 | 问题理解与自主拆解 | 1 | **1** | 以计分结构驱动拆解，并有实测基线作为结果证据 |
| U3 | 取舍与反思 | 1.5 | **1** | 学生给出外部线索（可能存在缺失条件），核对表与结论由 Agent 完成 |
| U4 | 实验与反馈迭代 | 1 | **1** | 学生提供环境能力边界，使实验循环可跑；结果证据为镜像模式实测 |

- 乐观合计 **5**，严格合计 **4**。
- 未覆盖维度：**技术理解与迁移**（0 分）。
- **2 档单元数 = 0**。2 档要求『在同一实例中迁移到新场景，完成验证，并结合结果分析局限』，现有四条都缺少学生侧的迁移与局限分析。

## 2 结构性缺陷（比分数更重要）

1. **五个维度缺一个**：技术理解与迁移没有任何学生证据。规则明确『缺少某个维度的证据仅影响该维度』，但这一维度目前是 0。
2. **档位上不去**：四条都是『学生发起 + Agent 执行』的形态，天然卡在 1 档。要够 1.5 或 2，必须是学生本人解释结果、据此修正、并分析局限或迁移到新场景。
3. **U4 的证据链偏弱**：『提供环境信息』与『实验迭代』的因果距离较远，严格评审可能压到 0.5。

## 3 提分路径（按性价比排序）

| 优先级 | 动作 | 预期 |
| --- | --- | --- |
| 1 | 学生用自己的话解释一个机制（如『为什么单事务不需要 MVCC』『为什么 843MB 只占 85MiB』），并指出该思路还能用在哪 | 补上缺失维度，且有机会够 2 档 |
| 2 | 学生对某个技术选择给出判断并说明放弃条件（如 exact 与 ann 的取舍） | 独立验证维度加 1 分 |
| 3 | 学生解释一次实验结果并说明据此改了什么 | 把 U1/U3 从 1 推到 1.5 |

## 4 与提测额度的关系

官方材料分**只有在 MySQL case 全过之后才产生**。所以：
- 门槛没过就提测 → 拿到的是失败类别，材料分不产生（不浪费，但也不得分）。
- 自评是免费的，**应该先自评、再改材料、再提测**，这样一次提测能同时拿到『门槛结果 + 官方材料分 + 评审报告』。
