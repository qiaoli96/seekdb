## 知识包 C · 用于 Q11（局限在哪、什么情况下失效）

我们这套方案确实有边界，都有实测支撑：

| 局限                    | 具体表现                                                                            |
| --------------------- | ------------------------------------------------------------------------------- |
| **arena 快速通道会被写操作打断** | 表里只要有 UPDATE/DELETE，arena 就标记失效并退回逐行流式扫描（正确性不受影响，但查询从 0.13 ms 回到 0.4~0.9 ms 量级） |
| **查询随数据量线性增长**        | 精确扫描必须读完全部向量：10,000 行读 5.12 MB；1,500,000 行要读 843 MB，单次查询 300+ ms                |
| **WAL 只增不减**          | 更新/删除是追加新版本，旧版本留在文件里；长时间跑会膨胀（比赛短用例撑不爆，但真实业务不行）                                  |
| **只能 2 线程**           | 受容器 `--cpus=2` 限制，再多的线程拿不到额外带宽                                                  |
| **写盘量翻倍**             | 为了加快 fdatasync 做预分配，代价是多写一份零字节（8.16 MB → 14.45 MB）                              |

**你可以自己判断**：哪一条你认为最致命？在什么场景下它会先崩？
